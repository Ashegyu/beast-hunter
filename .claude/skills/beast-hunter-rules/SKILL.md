# beast-hunter-rules

CLAUDE.md에서 옮겨 온 작업 메모. 내용이 바뀌면 이 파일을 고친다.

## 게임 규칙 요약
- 자동 회피(0.135, 사용자 요청): 몬스터 예고 공격·투사체를 30%만 피한다(`AUTO_DODGE_CHANCE`, `autoDodges(kind,id,salt)` 해시 판정, 전투 난수 불변). 폭발핵 회피·흘려베기 자동 사용은 그대로. 이에 맞춰 일반 몬스터 피해 `THREAT.mob` 3→2, 보스 관문 ×1.2→1.1, 방어 태세 보스 약점 노출 중 관문 감소는 대응률만큼 줄어듦(`e.gateCounter`).
- 일반 몬스터 피해 배율(0.134, 사용자 요청, `THREAT.mob`, 보스·던전·레이드 제외, 0.135부터 ×2): 그 전엔 일반 스테이지 피해가 최대 체력의 1~8%뿐이었다. 시뮬 `HPLOG=1`이 스테이지당 피해·회복을 집계한다.
- 난이도 곡선·관문(0.133, 사용자 요청 '점점 어렵게, 빌드를 안 바꾸고 스펙업도 안 하면 못 깨는 구간'): 적 체력·피해는 `chapters.js` `THREAT`(체력 1.012^(c−1)×1.12^(지역−1), 피해 1.014·1.12)를 기존 `multiplier`에 곱한 `hpScale`/`damageScale`(`bossHp`도 hpScale 기준, 레이드는 `raidBossHp` 옛 수치, 보상은 multiplier). 엔진 spawnEnemy가 `s.enemyScale={hp,damage}`(시험·시뮬용 덮어쓰기)를 곱한다. 관문 `stage-gates.js`: 챕터 보스(생태 bossRule→유형 `BOSS_GATE_BY_RULE`) + 챕터마다 스테이지 하나(`GATE_STAGES[(c−1)%3]`=7/9/6, 보스와 다른 유형). 유형 survival(적 피해)·swarm(일반 괴수 체력)·single(정예·보스 체력)·defense(적이 받는 피해, `e.gateGuard`). 압력 `gatePressure`=.4+.012(c−1)+.15×지역, 보스 ×1.2. 대응 `gateCounter`=갈래 노드×.15(최대 .75)+스킬×.1(최대 .4), `COUNTER_REDUCTION` .75. prepareStage가 `s.run.gate`(=gateEffect, 던전·레이드 null)를 정하고 spawnEnemy가 적용. 시뮬 `tools/simulate-campaign0133.mjs <dist> <시드> [마지막] [idle|spec|switch|adapt]`(STUCK_AFTER 환경변수), 결과 tools/reports/alpha0133-difficulty.txt. 조정은 dist의 js만 복사한 변형 폴더에서 수치를 sed로 바꿔 4정책을 병렬로(정책당 20~40분). **후반(5~6지역)은 스펙업만으로는 못 깨고 빌드도 바꿔야 하는 것이 의도(사용자 결정)** — 강화 수치를 키워 스펙업만으로 넘게 만들지 말 것.
- 스테이지 별(0.132, `stage-stars.js`, 사용자 요청): 클리어마다 ★ 클리어 · ★ 제한 시간 절반(30초) 안 · ★2·★3 시간은 0.135부터 스테이지별 `STAR_TIMES`(1~9는 [빠른, 최속], 보스는 [35초, 체력 50%]; 몬스터 등장·이동 때문에 최단 시간이 17~37초라 한 기준은 불가능했음), 보스 ★3만 스테이지 중 최저 체력 50% 이상(`starsFor({stage,...})`, 비트 이름 `third`)(`s.run.lowestHp`, hurtPlayer가 갱신, prepareStage가 1로; 클리어 순간 체력은 시뮬에서 100% 충족이라 바꿈). `recordStageClear`가 `awardStars`로 최고 기록을 OR로 합치고 `s.run.stars`·stageClear 효과의 `stars/gained`에 남긴다(던전·레이드 제외, 난이도 무관). 저장 `profile.stageStars`(챕터당 30비트 정수)·`starChests`(챕터당 3비트), stageStars는 battle-progress의 REWARD/PROGRESS 항목. 복원은 깬 스테이지만 남기고, 필드 없는 옛 저장은 깬 스테이지에 ★1. 챕터 상자 ★10/20/30 `claimStarChest(s,챕터,1~3)`(거점 전용, `starChestReward`), ★30 상자는 성장 포인트 +1(`growth.bonusGrowthPoints`, `cleanTraining`의 세 번째 인자). UI: 지도 오른쪽 `#map-star-chests`(`map-star-count`, `star-chest-1~3`, `map-star-note`), 스테이지 상태 글자 ★☆☆(`data-stars`), 지도 미리보기의 지역 원화는 자리 때문에 숨김(layout-fit.css 0.132 블록). 테스트에서 클리어를 만들 땐 `s.run.lowestHp`를 직접 둔다(tests/stage-stars.test.mjs `clearStage`).
- 난이도 개편(0.139, 사용자 결정): 정예는 일반 60장 전부 클리어 후, 악몽은 정예 60장 전부 클리어 후 열리고 각 모드 안에서는 한 장씩(`modeOpen(p,d)`=모든 챕터 bossMastery≥d−1, `bossModeAvailable`=modeOpen && (1장 || 앞 장 mastery≥d)). 강도는 곡선 이어가기: `modeScale(id,d)`={hp,damage,reward,chapter}=가상 챕터 `modeChapter`(정예 60+N×0.5, 악몽 90+N×0.5, `MODE_STEP`)의 `enemyHpScale`/`enemyDamageScale`/`chapterMultiplier` 비율(지역 점프는 6지역에서 멈춤, `threat`). spawnEnemy가 hp·damage·보스 투사체(`projectileDamageScale`)에, 보스 골드가 reward에 곱한다. `HUNT_MODES`의 hp/damage/reward 필드는 없앰, `xp`(악몽 0) 추가 — 줍는 경험치에 곱함. 악몽 기록 `profile.nightmareRecords`(챕터별 최단 보스 스테이지 초, `s.run.nightmareRecord={time,best}`, REWARD/PROGRESS 저널 필드). 테스트에서 정예·악몽을 열 땐 `tests/mode-fixture.mjs` `openMode(g,p,mode,chapter)`(모든 챕터 클리어 + 앞 챕터를 그 모드로 처치). 개방 뒤엔 지도가 기본으로 60장을 고르므로 UI 테스트는 `pickChapter`로 챕터를 고르고, 챕터 어셋 때문에 출발 뒤 `await ui.settle()`. 시뮬 `MODES=1`은 일반 60 → 정예 1~60 → 악몽 1~60을 순서대로.
- 정예·악몽 추가 배율(0.148.9, 사용자 결정 '단계별로'): chapters.js `MODE_EXTRA`/`modeExtra(id,d)`가 modeScale의 hp·damage에 곱해진다(정예 hp 2→3·damage .9→.6, 악몽 damage .85→.6, 악몽 hp 4→5·damage .85→.8, 1장→60장 선형). 레이드 난이도(modeScale(60,tier))도 같이 오른다. 기준: 정예 = 고대 +20 장비, 악몽 = 레이드·승화 +40 이상이 60장에서 30~45초. 측정 `node tools/benchmark-endgame0148.mjs`(약 45초, tools/reports/endgame-difficulty-0148.md). 0.148.10: 방어 태세(defense) 보스는 정예·악몽에서 약점 노출 한 번에 `exposeCap(장)`(30%→50%)까지만, 넘는 피해는 `EXPOSE_OVER` 0.2 (damageEnemy, `e.exposeWindow`/`exposeStartHp`, 12초 창 = floor(run.time/12)). 자동 전투가 노출까지 폭딜을 아껴 노출 한 번에 40~80%가 사라지던 것. 정예 60장 damage .75. 0.148.11: 정예·악몽 보스 체력만 `modeBossBump`(1 + MODE_BOSS_BUMP[d]·sin(π(장−1)/59), 정예 2.4·악몽 1.0)로 중간 장을 더 올림(spawnEnemy의 difficulty 분기, 보스만) — 30장 보스 30초 이상(사용자 요청). 0.148.12: 모양은 30장 중심 exp(−((장−30)/8)²)(사인은 45·50장 격노 보스를 벽으로 만들었다), 격노(fury) 보스는 정예·악몽에서 `MODE_FURY_HP`(2.5/2)·`MODE_FURY_DAMAGE`(.45/.25, 투사체 포함). 0.148.13: 소환(summon, 16~20·31~40장) 보스는 `MODE_SUMMON_HP` 2.2(40장 30초 이상). 0.148.14: 격노 HP 3.2/2.3·공격 .38/.2, 60장 보스 `MODE_FINAL_BOSS` 1.5/1.35, 노출 상한 [.3,.4], MODE_EXTRA 공격 60장 끝값 .6/.6. 목표: 30~60장 보스가 정예=고대 +20, 악몽=+40 이상으로 30초 이상(사용자 요청). 장별 측정 `CHAPTERS=10,15,…,60 node tools/benchmark-endgame0148.mjs` → endgame-chapters-0148.md.
- 정예·악몽 보정(0.139, 사용자 결정): 곡선 `MODE_STEP` .5(정예 60장=일반 90장, 악몽 60장=120장), 관문 압력 ×0.8(`MODE_GATE_PRESSURE`, `stageGate(c,n,d)`), 방어 태세 감소 `STANCE_GUARD`=[.7,.55,.55](`stanceGuard(s)`). 자동 스킬은 방어 태세 중 `STANCE_BURST`·궁극기를 약점 노출까지 아낌(`bossStanceLeft`, 훅 `stanceLeft`). 엔드 시뮬은 `MODES=1 ENDGAME=1`(리포트 tools/reports/alpha0139-difficulty-endgame.txt).
- 성장 콘텐츠(0.141, 사용자 요청·결정): 던전 `DUNGEON_MAX_LEVEL` 100, `dungeonPlan` hpScale/damageScale = 던전 배율 × `enemyHpScale/enemyDamageScale(dungeonChapter(L))`(1+(L−1)×0.9), spawnEnemy의 던전 분기는 스테이지 계수(factor)를 나눠 없앤다(보스 제외). 보상은 `dungeonRewards`(1~10 옛값, `past`로 완만). 신규 던전 `xp`(보상 `xp`, completeDungeon이 growthXp→gainXp)·`craft`(제작 재료). 초월 `transcendence.js`: `profile.transcendXp`(Lv.200에서만 복원, gainXp가 상한 뒤 남는 경험치를 넣음)·`profile.transcendence`{might,life,slayer,arts}(cleanTranscendence가 포인트로 자름), `transcendBonus`(damagePct·hpPct는 playerStats, bossDamage는 damageEnemy 첫머리, skillDamage는 combat-skills 시전 피해), 엔진 `trainTranscend`/`resetTranscendence`, 저널 REWARD에 두 필드. 무한의 탑: dungeons.js `TOWER`·`towerPlan`(`dungeonId 'tower'`, `s.run.stage`=층, `dungeonStageId`가 지형 챕터, 보스 층 wave에 `boss:true` → `dungeonActors`가 보스 actor), 일반 몬스터 THREAT.mob 적용, `completeTower`(첫 클리어만 보상, `profile.tower.best`, 저널 REWARD·PROGRESS), `towerBonus(best)`는 playerStats(damagePct·hpPct·crit·reduction). UI: 던전 `dungeon-mode-tower`·`#tower-panel`(`tower-floor-down10/down/up/up10`, `tower-floor`, `tower-best`, `tower-floor-info`, `tower-bonus`, `tower-next-bonus`), 앱 `selectedTowerFloor`, `startDungeon('tower',층)`. 성장 `growth-tab-transcend`·`#growth-transcend`(`transcend-<id>`, `transcend-level`). 주간 제한: 성장 던전마다 `DUNGEON_WEEKLY_CLEARS` 14회(새 단계 포함, completeDungeon에서 성공 때만 `profile.dungeonWeek.clears[id]`++, 주 = `raidWeek`, launchDungeon(s,id,level,view,now)가 남은 횟수 0이면 거부, 탑 제외), 깬 단계 반복은 `repeatRewards`(50%, 장신구 확률 ×0.5), 결과 `s.run.dungeonReward.repeat`. 테스트 tests/tower.test.mjs, tests/transcendence.test.mjs. 트리 프리셋 `profile.treePresets`(5칸 {name,tree}, 복원은 cleanTree, 불러오기는 fitTree), UI `tree-preset-<n>`·`tree-preset-save/load`, 확대 `tree-zoom-in/out/reset`·`tree-zoom-level`(앱 `treeZoom`, `#tree-web` transform). 단련·초월 행은 `train-row-<id>`/`transcend-row-<id>`(`.stat-row`), ＋ 버튼이 `train-<id>`/`transcend-<id>`, 게이지 `-gauge`. **100단계·탑 고층 난이도는 시뮬레이션으로 재지 않았다.**
- 레이드 난이도(0.139, 사용자 요청·결정): `launchRaid(s,id,now,view,tier)`, `s.run.raidTier`, `raidTierUnlocked(p,t)`(0=일반 60장, t≥1=모든 bossMastery≥t), 입장 공유. spawnEnemy가 레이드 적 전부에 `modeScale(MODE_CHAPTERS,tier)` hp·damage(보스는 projectileDamageScale), completeRaid 골드 ×reward·재료 ×(1+tier), 고대는 `rollAncient({…,raid,hunt:tier})` → `hunt`가 능력치(HUNT_POWER)와 `ancientSignatures`의 레이드 분기(위력 RAID_TIER_POWER, 정예 각성·악몽 심연 추가, id `<고대>-awaken/-abyss`, index 168~173)를 정한다. 이름엔 난이도를 붙이지 않음(복원이 카탈로그 이름으로 되돌림; UI는 huntGrade로 '정예 · ' 표시). UI `raid-tier-label`/`raid-tier`(옵션 `raid-tier-<t>`), 앱 `selectedRaidTier`. 시뮬 ENDGAME은 `raidTopTier`로 입장.

- 빌드 태그 밸런스(측정 `node tools/benchmark-branches0146.mjs` → `tools/reports/branches-benchmark-0146.md`, Codex 작성, 약 200초, Lv200 무장비 30장 9·10구간): 0.147.8 조정 뒤 태그 평균 DPS 검기 +6.4%·돌진 +7.4%·영역 +8.2%(보스 +15%)·일격 +4.1%·잔상 +7.9%. 0.147.6에선 영역이 보스 +62%였다 — 잔류 영역(`zone`) 틱이 경직을 쌓아 보스를 무너뜨린 탓이라 zone 틱은 poise 0(combat-skills.js). 돌진 태그 스킬은 3개뿐이라 돌진 보너스는 2·3개 두 줄. 잔상: 혈월의 칼날이 다른 스킬 시전에 끊기므로(combat-skills castSkill) 잔상 3개 보너스가 `keepBlade`(그 스킬은 칼날을 끊지 않음)를 준다 — 0.147.7까지 잔상 태그는 −2.3%로 손해였음. 버프형 스킬은 damage·primed가 거의 안 먹으니 태그 보너스는 duration·power·규칙으로. 개별 갈래 ±3% 이내 151개(조건부 갈래는 자동 전투에서 발동이 적을 수 있어 무용 확정 아님), 생존율은 모두 100%라 방어 갈래 구분 못 함. 한 태그만 빠르게 볼 땐 scratchpad에 이 스크립트의 tagBuilds·fight만 떼어 쓰면 1분 안쪽.
