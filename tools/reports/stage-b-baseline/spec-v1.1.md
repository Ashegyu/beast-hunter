# 모바일 핵앤슬래시 RPG — 챕터·던전·빌드·엔드 콘텐츠 통합 구현 명세

> **용도:** ChatGPT Work가 **기존 Sites 게임 프로젝트**를 분석하고, 이 문서를 기반으로 실제 게임에 기능을 단계적으로 적용하기 위한 작업 지시서
> **문서 상태:** 구현용 요구사항 / v1.1
> **목표:** 적은 종류의 콘텐츠로도 빌드 연구·전투 조건 변화·성장·도전이 순환하며 장기적으로 플레이할 수 있는 자동사냥 기반 핵앤슬래시 RPG
> **중요:** 이 문서의 수치 중 `[결정값]`으로 표시한 것은 기획자가 정한 초기값이다. 에이전트가 임의로 바꾸지 않는다. 단, **기존 게임에 이미 같은 목적의 규칙·수치가 있으면 기존 값을 우선**하고, 충돌 내용을 보고에 적는다.

### v1.0 → v1.1 변경 요약

- 1.1의 하드 카운터 문장 오타 수정 (의미가 반대로 읽히던 문제)
- 특수 스테이지는 "삽입"이 아니라 **기존 10스테이지 중 일부의 타입 재지정**으로 확정
- 효과 중첩 방식, 실패 보상, 콘텐츠별 제한 시간, 밸런스 목표치를 `[결정값]`으로 명시
- 고유 효과 장비와 엔드 콘텐츠 특수 장비의 **획득 경로** 추가 (새 아트 없이 기존 베이스 재사용)
- 모바일 검증 **뷰포트 크기** 지정
- 작업 전 **세이브 백업** 단계 추가
- 작업을 **단계별 개별 요청**으로 나누는 실행 방식 추가 (부록 참고)

## 0. Work 실행 지시 — 먼저 읽을 것

### 0.1 작업 대상과 원칙

- **현재 Work에 연결된 기존 Sites 게임 프로젝트를 수정한다.** 별도 게임이나 새 사이트를 만들지 않는다.
- **프로젝트 이름이나 사이트 slug를 추측하지 않는다.** 대상이 불명확하면 사용 가능한 프로젝트 목록에서 식별하고, 그래도 불명확하면 작업을 멈추고 질문한다. 다른 프로젝트를 임의 수정하지 않는다.
- 기존 캐릭터·몬스터·장비 이미지, 등급별 후광, 맵·스테이지 이미지, UI 스타일, 데이터는 **재사용**한다. 요구하지 않은 전면 리디자인과 새 아트 생성은 금지한다.
- **스마트폰 가로 모드 전용** 방향을 유지한다.
- 기존 **챕터당 10스테이지**, **60초 사냥 흐름**, **일반/정예/악몽 난이도**, **장비·제작·성장·자동 전투**는 삭제하지 않고 확장한다.
- 단순 이미지나 클릭되지 않는 메뉴를 구현 완료로 취급하지 않는다. 각 콘텐츠는 **진입 → 전투 → 승패 → 보상 → 저장 → 재진입** 경로가 실제로 동작해야 한다.
- 대규모 일괄 교체보다 **최소 변경으로 단계적으로 통합**한다.
- 사용자 PC에서 작업하거나 외부 서비스에 임의 로그인하지 않는다. Work와 연결된 Sites 편집 환경 안에서만 진행한다.

### 0.2 작업 시작 전 필수 절차

1. **세이브 백업:** 현재 저장 구조(키 이름·필드·버전)를 기록하고, 테스트용 기존 세이브 샘플을 보존한다. 마이그레이션 검증은 이 샘플로 한다.
2. **기존 구현 분석:** 아래 항목을 확인해 보고한다.
   1. 화면 목록과 라우팅/탭 구조
   2. 챕터·스테이지·난이도·전투·승패·보상의 데이터 흐름
   3. 장비 인스턴스 ID, 강화/승급/제작, 스킬, 인벤토리, 재화 저장 방식
   4. 저장소 종류(localStorage/IndexedDB/서버 등), 저장 시점, 복구 방식
   5. 전투 시뮬레이션과 시각 이펙트의 결합 정도
   6. 모바일 가로 레이아웃과 리사이즈 대응 방식
   7. 이미 존재하는 던전·레이드·프리셋·고유 효과·부가 옵션 유사 기능
   8. 이 명세의 `[결정값]`과 충돌하는 기존 규칙·수치 목록
3. 분석 없이 설계를 덮어씌우지 않는다.

### 0.3 우선순위

- **P0:** 기존 동작·세이브 보존, 장비 고유 효과 + 빌드 프리셋, 챕터 특수/정예/보스 스테이지
- **P1:** 성장 재료 던전 4종, 캠페인 완료 기반 엔드 콘텐츠 해금, 레이드·도전의 탑
- **P2:** 무한 학살·생존의 시련·보스 러시, 보상·밸런스·UI 고도화

**P0 → P1 → P2 순서로 실제 기능을 완성하고 검증한다.** 한 요청에서 모든 단계를 처리하려 하지 않는다. 각 단계 종료 시 보고하고 다음 지시를 기다린다(부록 A 참고). 구현하지 않은 항목은 '구현 완료'로 표시하지 않는다.

## 1. 게임 설계 목표

### 1.1 핵심 원칙

- 반복 사냥을 없애는 것이 목적이 아니다. **같은 콘텐츠라도 빌드·전투 조건·목표에 따라 공략 경험이 달라지게 한다.**
- 강해지는 재미(수직 성장)와 다른 플레이 방식이 생기는 재미(수평 성장)를 함께 제공한다.
- **특정 빌드가 없으면 클리어할 수 없는 하드 카운터 구조는 만들지 않는다.** 적합한 빌드는 시간·안정성·효율에서 우위를 갖고, 다른 빌드도 성장하면 클리어할 수 있어야 한다.
- 콘텐츠가 서로 연결되어야 한다. 챕터에서 장비를 얻고, 던전에서 재료를 수급하고, 빌드를 조합해 엔드 콘텐츠를 공략하고, 보상으로 다시 성장하거나 새 빌드를 만든다.
- 과도한 일일 숙제, 불필요한 반복 클릭, 비싼 빌드 변경 비용을 피한다.

### 1.2 밸런스 목표 `[결정값]`

| 항목 | 목표 |
|---|---|
| 추천 빌드의 우위 | 같은 전투력 기준으로 클리어 시간 **20~40% 단축**, 또는 생존 콘텐츠에서 남은 체력 여유가 뚜렷함 |
| 비추천 빌드의 클리어 가능성 | 권장 전투력의 **+25% 수준**이면 비추천 빌드로도 클리어 가능 |
| 단일 빌드 지배 금지 | 초기 3빌드 각각이 최소 1개 콘텐츠 유형에서 가장 효율적이어야 함 |

에이전트는 단계 B 이후 3빌드로 대표 콘텐츠를 시뮬레이션해 위 목표의 충족 여부를 수치로 보고한다.

### 1.3 핵심 플레이 루프

```text
[챕터 전투 / 일반 파밍] ──> [장비·재화 획득]
           │                      │
           ▼                      ▼
[특수 스테이지·보스] <── [빌드 조합·프리셋]
           │                      ▲
           ▼                      │
[성장 재료 던전] ──> [강화·승급·스킬 성장]
           │                      │
           └──────────┬───────────┘
                      ▼
             [전체 챕터 클리어]
                      ▼
         [다양한 엔드 콘텐츠 개방]
            │       │       │
          레이드   도전탑  기타 도전
            └───────┼───────┘
                    ▼
         [기록 개선 / 고급 보상 / 새로운 빌드]
```

### 1.4 콘텐츠 역할 구분

| 영역 | 주요 역할 | 플레이어가 결정하는 것 |
|---|---|---|
| 챕터 | 진행·빌드 학습 | 어떤 빌드로 특수 구간과 보스를 돌파할까 |
| 일반 사냥 | 안정적 성장과 장비 파밍 | 어떤 프리셋으로 효율을 높일까 |
| 성장 던전 | 골드·강화·승급·스킬 재료 수급 | 어떤 던전을 얼마나 돌까 |
| 빌드/프리셋 | 콘텐츠 간 전략의 중심 | 장비·스킬·고유 효과 조합 |
| 엔드 콘텐츠 | 챕터 완주 후 장기 도전 | 콘텐츠별 최적화, 기록 개선 |

## 2. 챕터 구조 개편

### 2.1 스테이지 타입 재지정 `[결정값]`

- **챕터당 10스테이지를 유지한다. 스테이지를 새로 끼워 넣지 않는다.** 기존 스테이지 일부의 `stageType`만 재지정한다.
- `stageType`과 기존 `difficulty`는 별개 필드다.
  - `stageType`: `normal` / `special` / `elite` / `boss`
  - `difficulty`: 일반 / 정예 / 악몽 (기존 명칭·수치 보존)
- 기본 배치(챕터 데이터로 변경 가능):

| 스테이지 | stageType | 의도 |
|---|---|---|
| 1~3 | normal | 기본 파밍과 준비 |
| 4 | special | 특정 전투 조건을 처음 제시 |
| 5~7 | normal | 장비 획득·빌드 개선 |
| 8 | elite | 조합된 몬스터와 강화 패턴 |
| 9 | special | 최종 보스 대비 |
| 10 | boss | 챕터 클리어 판정 |

- 기존 10스테이지에 이미 보스가 있다면 그것을 `boss`로 매핑하고 새로 만들지 않는다.

### 2.2 제한 시간 `[결정값]`

- normal / special / elite / boss 모두 **60초**. 기존 게임에서 보스 시간이 다르게 구현되어 있다면 기존 값을 유지하고 보고한다.
- special / elite / boss는 **60초 안에 조건 달성 시 성공**, 시간 초과 또는 사망 시 실패.

### 2.3 특수 스테이지

- 규칙 예: 방어형 몬스터 비중 증가, 원거리 압박, 지원형 몬스터 우선 제거, 다수 돌격, 분열형 몬스터.
- 전투 입장 패널에 **규칙 한 줄 + 유리한 특성**을 표시한다. 예: `고방어 몬스터 다수 — 방어 감소·출혈 유리`
- 장비 체크나 입장 제한은 두지 않는다.
- **실패 보상 `[결정값]`:** special / elite / boss 실패 시 보상 없음. normal은 기존 정책 유지.
- 실패 후 결과 화면에서 **재도전**과 **프리셋 변경 후 재도전**을 바로 할 수 있어야 한다.

### 2.4 챕터 보스

- 보스마다 최소 **하나의 고유 전투 의사결정 요소**가 있어야 한다.
- 예시 보스 **망각의 기사**:
  - 방어 태세: 받는 피해 70% 감소, 8초 지속 `[결정값]`
  - 방어 해제: 4초간 약점 노출, 받는 피해 30% 증가 `[결정값]`
  - 순간 화력·방어 감소 빌드가 유리하지만 다른 빌드도 성장으로 돌파 가능
- 다른 보스는 광역 소환, 지속 피해, 생존 압박, 정예 동시 출현 등 **서로 다른 대응 방식**을 요구한다.
- 보스 HP, 남은 시간, 현재 상태(방어/약점 등), 승패가 HUD에 명확히 보여야 한다.
- 챕터 완료는 **보스 클리어 정산이 성공적으로 저장된 이후**에만 확정한다.

### 2.5 진행 상태와 기존 세이브 처리

- 상태 전이: `잠금 → 입장 가능 → 진행 중 → 성공/실패 → 보상 확정 → 다음 스테이지 해금`
- 빠른 연타, 새로고침, 전투 종료 직후 이탈로 중복 클리어·중복 보상이 생기지 않아야 한다.
- **기존 세이브 마이그레이션 `[결정값]`:**
  - 이미 클리어한 스테이지는 타입이 special/elite로 바뀌어도 **클리어 상태 유지**.
  - 이미 받은 보상은 **다시 지급하지 않는다**.
  - 이미 클리어한 챕터는 다시 잠기지 않는다.
  - 신규 타입의 최초 클리어 보상이 생긴 경우, 기존에 클리어한 스테이지는 해당 보상을 **지급하지 않는다**(재클리어 보상만 적용).

## 3. 성장 재료 던전

### 3.1 던전 종류

| 던전 | 주요 획득 재료 | 전투 특징 | 추천 빌드 성격 |
|---|---|---|---|
| 골드 던전 | 골드 | 대량의 약한 적 | 광역·연쇄 처치 |
| 강화 던전 | 장비 강화 재료 | 체력이 높은 적 | 단일 화력·방어 감소 |
| 승급 던전 | 장비 승급 재료 | 강력한 정예 중심 | 지속 화력·생존 균형 |
| 스킬 던전 | 스킬 성장 재료 | 다양한 패턴 혼합 | 다목적 빌드 |

- 기존 강화·승급·스킬 재료가 있으면 **그 아이템에 연결**한다. 같은 목적의 새 재화를 만들지 않는다.
- 재료가 없으면 최소한만 추가하고, 획득처·소모처를 UI에서 확인할 수 있게 한다.
- 던전 단계가 오를수록 위험과 보상이 함께 증가한다. 제한 시간은 **60초** `[결정값]`.
- 반복 진입 가능. 실패 시 보상 없음 `[결정값]`.

### 3.2 던전과 엔드 콘텐츠의 차이

- 던전은 **안정적인 성장 공급**, 엔드 콘텐츠는 **공략·기록·특수 보상**이 중심.
- 매번 프리셋 변경을 강제하지 않는다.
- 입장권·스태미나·일일 제한은 **기존 게임에 없으면 새로 도입하지 않는다**.

### 3.3 UI

- 던전 카드: 이름, 보상 아이콘, 단계, 예상 보상, 현재 프리셋, 입장 버튼.
- 입장 → 자동 전투 → 성공/실패 → 보상 목록 → 재입장/나가기까지 구현.
- 획득 재료가 **강화/승급/스킬 화면에 즉시 반영**되어야 한다.

## 4. 엔드 콘텐츠

### 4.1 해금 원칙

- 데이터로 지정한 **캠페인 완료 조건**(모든 메인 챕터 보스 클리어)을 충족하면 개방한다.
- 현재 구현된 마지막 챕터가 최종 챕터인지 확인하고 보고한다. 챕터가 추가될 예정이면 해금 조건을 데이터에서 바꿀 수 있게 한다.
- **이미 해금된 플레이어는 챕터 추가 후에도 해금 상태를 유지한다** `[결정값]`.
- 해금 전에는 메뉴를 숨기지 않고 잠금 상태와 조건을 보여준다.

### 4.2 콘텐츠별 명세

| 콘텐츠 | 제한 시간 `[결정값]` | 성공 조건 | 기록 |
|---|---|---|---|
| 레이드 | 120초 | 보스 처치 | 처치 여부, 남은 시간, 최고 피해량 |
| 도전의 탑 | 층당 60초 | 층 규칙에 따른 조건 달성 | 최고층 |
| 무한 학살 | 60초 | 시간 종료까지 생존 (실패 없음, 점수 경쟁) | 최고 처치 수 |
| 생존의 시련 | 90초 | 90초 생존 | 최장 생존 시간 |
| 보스 러시 | 보스당 60초 | 기존 챕터 보스 5마리 연속 처치 | 연속 처치 수, 완주 시간 |

#### A. 레이드
- **싱글플레이 자동 전투**로 구현한다. 멀티플레이·랭킹을 가장하지 않는다.
- HP 단계(100~70% / 70~35% / 35~0%)마다 패턴이 바뀐다 `[결정값]`.
- 소환, 약점 노출, 부위 파괴 중 **현재 전투 엔진으로 처리 가능한 기믹**부터 구현한다.
- 실패해도 **누적 피해량 구간 보상**은 지급 `[결정값]`. 처치 보상은 성공 시에만.

#### B. 도전의 탑
- 각 층에 **서로 다른 규칙**을 지정한다. 체력·공격력 배수만 올리는 층은 금지.
- 규칙 예: 대군, 회복 효율 50% 감소, 중장갑, 몬스터 분열, 혼합 정예.
- 층 진입 전 규칙·유리한 특성·보상을 표시한다.
- 보상: **층별 최초 클리어 보상 1회 + 이미 클리어한 층 재도전 시 소량 반복 보상** `[결정값]`.
- 몬스터·맵 자산은 재사용한다.

#### C. 무한 학살
- 처치 수 최대화. 광역·연쇄 빌드의 재미를 확인하는 콘텐츠.
- 현재 처치 수, 최고 기록, 보상 구간 표시.
- **동시 몬스터 최대 60마리, 동시 이펙트 상한 적용** `[결정값]` (기기 보호).

#### D. 생존의 시련
- 방어·회복·피해 감소·제어 빌드가 유리하다.
- 자동 전투이므로 **수동 회피가 필요한 패턴은 만들지 않는다**.

#### E. 보스 러시
- 기존 챕터 보스를 순서대로 상대한다.
- 규칙 `[결정값]`: 플레이어 HP는 **보스 사이에 유지되며 최대 HP의 20% 회복**, 스킬 쿨다운은 **유지**.
- 규칙은 시작 전에 표시한다.

### 4.3 보상 방향

| 콘텐츠 | 1차 보상 |
|---|---|
| 레이드 | 엔드 전용 고유 효과 장비(4.4), 제작 재료 |
| 도전의 탑 | 최초 클리어 성장 보상 |
| 무한 학살 | 골드·공통 재료 |
| 생존의 시련 | 공통 재료·생존형 고유 효과 재료 |
| 보스 러시 | 특수 제작 재료 |

- 모든 콘텐츠를 매일 반복해야 성장하는 구조는 금지한다.
- 공통 재료는 여러 경로에서 얻을 수 있게 하고, 전용 보상만 차별화한다.

### 4.4 엔드 전용 장비 `[결정값]`

- **새 아트를 만들지 않는다.** 기존 장비 베이스 이미지 + 기존 등급 후광을 사용하고, **엔드 전용 고유 효과**로 차별화한다.
- 이름 앞에 콘텐츠 접두어를 붙여 구분한다. 예: `[레이드] 망각의 대검`

## 5. 장비·스킬·빌드 시스템

### 5.1 두 종류의 성장

- **수직 성장:** 레벨, 강화, 승급, 스킬 레벨
- **수평 성장:** 고유 효과, 스킬 조합, 특수 규칙 대응, 새 빌드

기존 등급·슬롯·제작·이미지·후광을 유지한다. 등급 체계를 개편하지 않는다.

### 5.2 고유 효과의 획득 경로 `[결정값]`

- 기존에 고유 효과 시스템이 있으면 그것을 사용한다.
- 없으면 장비 인스턴스에 **고유 효과 슬롯 1개**를 추가한다. 장비 이미지는 그대로다.
- 획득 경로:
  1. 챕터 special / elite / boss 스테이지 드랍 장비에 확률적으로 부여
  2. 제작 시 재료를 추가 소모해 특정 고유 효과를 지정 부여
  3. 엔드 콘텐츠 전용 장비(4.4)
- 기존에 가진 장비는 고유 효과 없이 유지되며, 제작 경로로 나중에 부여할 수 있다.

### 5.3 초기 고유 효과 `[결정값]`

| 효과 | 전투 동작 | 초기 수치 | 유리한 상황 |
|---|---|---|---|
| 번개 전이 | 타격 시 가까운 적에게 피해 전이 | 공격력 40%, 최대 3대상 | 다수 적 |
| 처치 폭발 | 처치 시 주변 범위 피해 | 공격력 60% | 밀집 적 |
| 출혈 | 적중 시 지속 피해 중첩 | 초당 공격력 8%, 최대 10중첩, 3초 | 고체력 적 |
| 처형 | 체력 25% 이하 대상 추가 피해 | +40% | 마무리 |
| 흡혈 | 준 피해 일부 회복 | 3% | 생존 |
| 광폭화 | 처치 후 공격속도 증가 | +20%, 3초 | 연속 처치 |
| 방어 감소 | 대상 방어력 감소 | -20%, 4초 | 보스 |
| 반격 | 피격 시 반격 | 20% 확률, 공격력 80% | 밀착 전투 |

### 5.4 계산 규칙 `[결정값]`

**계산 순서:** 기본 능력치 → 장비·패시브 보정 → 고유 효과 → 피해/회복 반영. 기존 전투 로직에 순서가 이미 있으면 기존을 따르고 보고한다.

**중첩 규칙:**
- 같은 고유 효과를 여러 장비에 장착: **수치 합산**, 단 효과별 상한 적용 (번개 전이 대상 수 최대 5, 흡혈 최대 10%, 방어 감소 최대 -40%)
- 서로 다른 출처의 % 증가: **같은 카테고리 안에서는 합산, 카테고리끼리는 곱연산** (예: 공격력 % 합산 × 치명타 피해 % 합산)
- 지속 시간형 버프·디버프의 재적용: **지속 시간 갱신, 수치는 최대값**

**연쇄 제한:**
- 번개 전이는 **재전이하지 않는다** (전이된 피해가 다시 전이 발동 불가).
- 처치 폭발로 처치된 적은 **다시 폭발하지 않는다** (연쇄 깊이 1).
- 반격은 반격으로 발동하지 않는다.
- 한 프레임에 처리하는 고유 효과 발동은 **최대 50회**, 초과분은 다음 프레임으로 이월하거나 버린다.

**데이터 단일화:** 전투 엔진과 UI 설명은 **같은 효과 정의 데이터**를 참조한다. 설명 문구에 수치를 하드코딩하지 않는다.

### 5.5 검증할 초기 3빌드

1. **대군 처리:** 번개 전이 + 처치 폭발 + 광폭화
2. **보스 화력:** 출혈 + 방어 감소 + 처형
3. **생존:** 피해 감소(기존 스탯) + 흡혈 + 반격

어느 빌드도 특정 콘텐츠에서 기능 자체가 봉쇄되지 않아야 한다.

## 6. 빌드 프리셋

### 6.1 요구사항

- **5개 슬롯**, 이름 수정 가능 (기본명: `일반 사냥`, `보스`, `광역`, `생존`, `실험`)
- 저장 항목: 장착 장비 인스턴스 ID, 스킬 구성, 스킬 우선순위, 패시브/특성. **기존에 없는 설정 항목을 위해 가짜 UI를 만들지 않는다.**
- 챕터·던전·엔드 콘텐츠 **입장 직전**에 선택·전환할 수 있어야 한다.
- 같은 장비를 여러 프리셋이 **공유 참조**한다. 복제하지 않는다.
- 전환은 **원자적으로** 적용한다. 중간 상태가 보이거나 저장되지 않는다.
- 프리셋 전환에 비용을 붙이지 않는다.
- 전투 중 장비 교체 금지 정책이 있으면 유지한다.

### 6.2 불변 조건

1. 소유하지 않은 장비 인스턴스는 장착할 수 없다.
2. 같은 인스턴스가 배타적인 두 슬롯에 동시에 장착되지 않는다.
3. 프리셋은 장비를 소유하지 않고 **인스턴스 ID만 참조**한다.
4. 강화·승급 후에도 인스턴스 ID는 유지되며, 모든 참조 프리셋에 결과가 반영된다.
5. **유효하지 않은 참조 처리 `[결정값]`:** 전환 시 유효한 항목만 장착하고 빈 슬롯은 비워 둔 뒤, `○개 장비를 찾을 수 없어 비워 두었습니다` 안내를 표시한다. 프리셋 화면에는 해당 슬롯에 경고 표시.
6. 저장과 UI 표시는 전환 확정 후 일치해야 한다.

### 6.3 UI

- 입장 패널: 현재 프리셋 이름 + 변경 버튼. **두 번 이하의 탭으로 전환**.
- 프리셋 편집 화면: 장비·스킬·고유 효과 차이가 한눈에 보이게.
- 전환 후 장착 상태와 표시 능력치가 즉시 갱신된다.

## 7. 진행·보상·저장 데이터

> 클래스 구조를 강제하지 않는다. 아래는 **반드시 지켜야 할 상태와 소유권**이다.

### 7.1 상태 구분

**정적 정의 데이터:** 챕터/스테이지 정의, stageType, 난이도 파라미터, 몬스터 역할, 보스 패턴, 던전 정의·드랍 테이블, 엔드 콘텐츠 정의·해금 조건, 고유 효과 정의

**영구 저장 플레이어 상태:** 클리어 기록, 엔드 콘텐츠 해금·기록, 장비 인스턴스(고유 효과 포함), 재료 수량, 강화·승급·스킬 성장, 프리셋과 현재 선택, 1회성 보상 수령 기록

**전투 세션 임시 상태:** 콘텐츠 ID, 난이도, 시작 시점 빌드 스냅샷, 남은 시간, HP, 버프·디버프, 처치 수, 임시 보상 계산

세션 상태와 영구 상태를 섞지 않는다. 새로고침으로 승패가 뒤틀리면 안 된다. **전투 중 새로고침 시 해당 전투는 실패 처리하고 보상 없음** `[결정값]`.

### 7.2 보상 정산 불변 조건

- 한 전투 결과에 대해 보상은 **한 번만** 확정한다.
- 성공 확인 → 보상 산출 → 재화·아이템 반영 → 클리어 기록 갱신 → 저장을 **하나의 정산 단위**로 처리한다. 전투마다 고유 ID를 발급하고, 정산 완료 ID를 기록해 중복을 막는다.
- 강화·승급은 재료 확인 후 소모. **음수 재고 금지**.
- 연타·중복 클릭·재접속 재전송으로 보상이 중복 적용되지 않는다.
- 로컬 저장만 쓰는 구조라면 **치팅 방지나 서버 권위성은 보장되지 않는다**는 한계를 보고에 적는다. 백엔드를 새로 만들지 않는다.

### 7.3 저장 마이그레이션

- 기존 키·필드·값을 초기화하지 않는다.
- 저장 데이터에 **스키마 버전 필드**를 두고, 이전 버전 세이브를 읽으면 기본값을 채워 올린다.
- 0.2에서 보존한 **기존 세이브 샘플로 마이그레이션을 실제 검증**한다.

## 8. UI/UX (모바일 가로 전용)

### 8.1 공통 원칙

- 기존 비주얼 콘셉트, 이미지, 아이콘, **등급별 후광**, 배경 질감을 유지한다.
- 새로 필요한 화면만 기존 스타일로 확장한다.
- 안전영역(safe area), 주소창, 비율 변화를 고려한다. 작은 화면에서는 핵심 전투 정보와 주 액션이 우선이다.
- 좁은 화면에서는 컨트롤을 축소하기보다 탭/패널로 나눈다.
- 구현되지 않은 기능을 클릭 가능한 것처럼 보이게 하지 않는다.

### 8.2 검증 뷰포트 `[결정값]`

| 크기 (가로×세로, CSS px) | 대표 기기 |
|---|---|
| 667×375 | 소형 iPhone |
| 740×360 | 소형 Android |
| 844×390 | 표준 iPhone |
| 932×430 | 대형 iPhone |

새로 추가하거나 수정한 모든 화면을 4개 뷰포트에서 확인하고 **스크린샷을 보고에 첨부**한다.

### 8.3 화면

1. **챕터 선택:** 10스테이지 진행, stageType 배지, 기존 난이도 선택, 특수 규칙·유리한 특성, 프리셋 변경
2. **던전 선택:** 4종 카드, 재료 아이콘·현재 수량, 입장·결과
3. **빌드 관리:** 프리셋 5개, 이름, 장비, 스킬, 고유 효과, 유효하지 않은 참조 경고
4. **엔드 콘텐츠:** 5종, 잠금·해금 조건, 기록, 입장
5. **전투 HUD:** 콘텐츠별 필요한 정보만. 공통: 남은 시간, 핵심 진행 수치, 일시정지/나가기, 승패. 일반 사냥 HUD는 기존 구성 유지
6. **결과 화면:** 성공/실패, 핵심 통계, 획득 보상, 재도전 / 프리셋 변경 후 재도전 / 나가기

## 9. 구현 단계

각 단계는 **별도 요청**으로 진행한다. 단계가 끝나면 11장 형식으로 보고하고 다음 지시를 기다린다.

### 단계 A — 분석 (코드 수정 없음)
- 0.2 절차 수행: 세이브 백업 + 기존 구현 분석 + `[결정값]` 충돌 목록
- 이 명세를 적용할 때 바뀔 파일과 영향 범위 추정
- **이 단계에서는 코드를 수정하지 않는다.**

### 단계 B — P0
- 고유 효과 시스템과 계산 규칙(5장), 획득 경로
- 프리셋(6장)
- 챕터 stageType 재지정, 특수·정예·보스(2장), 세이브 마이그레이션
- 초기 3빌드 동작 확인과 1.2 밸런스 목표 측정
- 기존 60초 사냥·난이도 회귀 테스트

### 단계 C — P1-1: 성장 던전
- 4종 던전을 실제 전투·재료에 연결
- 재입장·정산 중복·재료 부족 테스트

### 단계 D — P1-2: 엔드 콘텐츠 해금 + 레이드·도전의 탑
- 캠페인 완료 검증 로직 하나
- 레이드·도전의 탑을 전투·보상·기록 저장까지 완성
- 나머지 3종은 잠금 + "준비 중" 표시 (구현 완료와 명확히 구분)

### 단계 E — P2
- 무한 학살·생존의 시련·보스 러시
- 성능 점검: 프레임 시간, 동시 몬스터·이펙트 수, 메모리
- 전체 UI 회귀 점검

## 10. 수용 테스트

실제 사이트에서 재현 가능해야 한다. 스크린샷만으로 통과 처리하지 않는다. 해당 단계에 속한 항목만 검증 대상이다.

### 기존 동작 보존 (모든 단계)
- [ ] 0.2에서 보존한 기존 세이브로 접속해 장비·재화·진행도·이미지가 유지된다.
- [ ] 8.2의 4개 뷰포트에서 겹침·잘림·의도치 않은 빈 공간이 없다.
- [ ] 일반 사냥 60초, 일반/정예/악몽 선택, 기존 보상·화면 전환이 정상이다.

### 챕터 (B)
- [ ] 특수 스테이지에서 규칙 차이를 실제로 확인할 수 있다.
- [ ] 추천과 다른 빌드로도 입장·전투가 된다.
- [ ] 보스 성공 후에만 챕터 완료가 저장된다. 실패·중단 시 기록되지 않는다.
- [ ] 이미 클리어한 스테이지·챕터가 마이그레이션 후에도 클리어 상태이고 보상이 재지급되지 않는다.

### 빌드/프리셋 (B)
- [ ] 프리셋 5개 생성·명명·저장·전환, 새로고침 후 복구.
- [ ] 공유 장비가 복제되지 않고, 강화 결과가 모든 참조 프리셋에 반영된다.
- [ ] 장비 분해 후 해당 프리셋 전환 시 빈 슬롯 + 안내가 표시된다.
- [ ] 3빌드의 처치 속도·생존·보스 피해 차이가 1.2 목표 범위 안인지 수치로 보고된다.
- [ ] 번개 전이·처치 폭발이 연쇄 제한을 지키고, 무한 학살 수준의 밀집에서도 프레임이 무너지지 않는다.

### 던전 (C)
- [ ] 4종 진입부터 결과까지 동작한다.
- [ ] 획득 재료가 인벤토리와 강화·승급·스킬 화면에 동일하게 반영된다.
- [ ] 재료 부족 시 강화가 막히고 재고가 음수가 되지 않는다.
- [ ] 중복 클릭으로 보상·비용이 두 번 적용되지 않는다.

### 엔드 콘텐츠 (D, E)
- [ ] 캠페인 완료 전 잠금, 완료 후 해금, 새로고침 후 유지.
- [ ] 레이드 HP 단계별 패턴 전환과 보상이 실제 결과와 연결된다.
- [ ] 도전의 탑 층별 규칙·해금·최고층 기록·최초 클리어 보상 1회가 동작한다.
- [ ] (E) 무한 학살·생존·보스 러시 각각 고유한 판정과 기록이 동작한다.
- [ ] 최고 기록이 낮은 기록으로 덮어쓰이지 않는다.
- [ ] 같은 결과의 보상을 다시 받을 수 없다.

### 실패 경로·성능 (모든 단계)
- [ ] 전투 중 새로고침 → 실패 처리, 보상 없음, 상태 꼬임 없음.
- [ ] 연속 입장 클릭·보상 팝업 중복 확인으로 상태가 꼬이지 않는다.
- [ ] 결과 화면이 전투 종료 전에 뜨거나, 종료 후 입력이 영구 잠기지 않는다.

## 11. 단계별 보고 형식

각 단계 종료 시 한국어로 보고한다.

1. 수정한 실제 프로젝트명과 적용 범위
2. **실제로 동작하는 기능** (데이터·전투·보상·저장까지 연결된 것만)
3. **구현하지 않은 항목과 이유** (화면만 있는 기능은 명시)
4. `[결정값]`과 기존 게임 규칙이 충돌한 항목과 처리 방식
5. 세이브 호환성·4개 뷰포트 점검 결과 (스크린샷 첨부)
6. 통과한 수용 테스트, 확인하지 못한 위험
7. 미리보기 링크 (가능한 경우)
8. 다음 단계에서 먼저 결정이 필요한 사항

'완료'는 클릭 가능한 화면이 아니라 **데이터·전투·보상·저장까지 연결된 경우에만** 쓴다.

## 12. 개발 원칙 요약

- 기존 게임을 버리지 말 것. 전투·자산·UI·보상·난이도를 유지하며 확장.
- 빌드 연구가 중심. 장비 하나가 모든 콘텐츠를 지배하지 않게.
- 콘텐츠별로 요구 특성이 달라야 한다. HP·공격력 배수만으로 차별화하지 않는다.
- 파밍 던전은 성장 공급, 엔드 콘텐츠는 공략과 기록.
- 프리셋은 필수 UX.
- 보상은 한 번만.
- 기존 플레이어를 초기화하지 말 것.
- 실제 기능부터. 장식용 화면과 과장된 완료 보고 금지.
- 재미는 검증할 것. 초기 3빌드로 실제 선택과 반복 의지를 확인한 뒤 확장.
