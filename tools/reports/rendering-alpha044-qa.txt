Alpha0.44 combat raster quality,2026-10-16

Observed causes
app.js resized canvas to logical viewport/2 and drew through a fixed0.5 transform; arena CSS requested pixelated re-expansion. No device DPI support.
390x844 browser: actual canvas CSS388x844,logical720x1566,backing360x783,DPR1 before change.
High-resolution scenery/character minification used nearest-neighbor globally, producing unstable high-frequency detail.
Regional monster sources have roughly54-90px body heights: forest guardian90,ruins king70,frost king69 for south walk frame0,while world heights250/244/254. Those source limitations are real and remain.

Chosen implementation
Separate render surface from existing camera units. Backing uses CSS dimensions times actual DPR,cap DPR2,2097152pixels,edge4096. Invalid geometry safely falls back to1200x760.
draw uses backing/logical scale per axis; camera,world transforms,attack geometry and pointer conversion remain unchanged.
Filter minified sprites/terrain at high quality; do not blur magnified low-resolution sprite frames. CSS arena image-rendering:auto,not pixelated whole-canvas re-expansion.
Handle DPI-only transitions without clearing held movement/attacks; aspect/camera changes still release controls.
Half-device-pixel terrain bleed eliminates filtered tile-edge gaps without changing tile positions or collision data.
Versioned view-controls import and top-level0.44 asset queries prevent mixing cached old modules/CSS with the new renderer.
No new frame allocations for surface state: dimensions computed only on resize/DPI transition; two numeric scale factors used in draw.
