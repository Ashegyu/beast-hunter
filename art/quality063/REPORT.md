# Alpha 0.63 — 첫 궁극기까지의 성장 속도

## 목표와 선택

궁극기는 Lv.20에 열리지만 장착은 거점에서 한다. 목표는 2챕터 종료 전 해금 → 챕터 사이 거점에서 명시적으로 장착 → 3챕터에서 실제 사용이다. 장착 구성의 자동 교체는 하지 않는다.

레벨당 필요 경험치를 낮추는 안은 기존 저장 경험치의 비율 변환과 이관을 요구한다. 해금 레벨을 낮추는 안은 기존 스킬 표와 궁극기 자동 강화 구간까지 바꾼다. 이번에는 필요 경험치와 저장 형식을 유지하고 새로 획득하는 경험치에 레벨 구간 배율을 적용했다.

| 캐릭터 레벨 | 사냥·정찰 성장 경험치 |
| --- | --- |
| 1~4 | 1배 |
| 5~19 | 4배 |
| 20~39 | 2배 |
| 40~50 | 1배 |

기존 재료 감각의 경험치 증가는 먼저 계산하고 성장 배율을 적용한다. Lv.50의 성장은 기존대로 끝나며, 결과 화면의 획득 경험치는 계속 표시한다. 성장 화면에 현재 배율과 다음 구간을 안내하고, 결과 경험치의 title에는 배율 적용 전 경험치와 성장 보너스를 남긴다.

## 후보 측정

균형/광역/안정의 세 거점 정비 정책과 시작 사냥 시드 0/4/9의 9개 경로를 후보별로 실행했다. 실제 보유 장비와 강화 예산을 사용하며, 새 궁극기는 챕터 사이 거점 정비 단계에서 장착했다. 모든 후보의 9경로가 3챕터를 완료했다.

| Lv.5~19 배율 | Lv.20~39 배율 | 3챕터 완료 레벨 | Lv.20 도달 | 실제 첫 궁극기 사용 |
| --- | --- | --- | --- | --- |
| 기존 1배 | 1배 | 14 | 미도달 | 없음 |
| 2배 | 2배 | 19 | 미도달 | 없음 |
| 3배 | 2배 | 21 | 3챕터 | 거점 장착 전이라 없음 |
| **4배** | **2배** | **23** | **2챕터 5스테이지** | **3챕터 3스테이지** |

선택한 안은 실제 프로덕션 엔진에서도 후보와 동일한 측정 상태/행동 결과를 냈다. 9경로의 챕터 종료 레벨은 모두 15/20/23이었다. 이 표는 결정적 시뮬레이션 결과이며 플레이어 전체 분포나 실제 기기 플레이 시간의 보장은 아니다. 이전 한 경로의 Lv.15 결과와는 거점 숙련/장비 선택 정책이 다르다.

Lv.20·캠페인 완료·3000골드의 별도 합성 프로필로 빙하 보스 재도전을 이어 갔다. 세 정책 모두 23회에 Lv.30, 60회에 Lv.40에 도달했고 패배는 없었다. 누적 시뮬레이션 전투 시간은 Lv.30까지 약 704~770초, Lv.40까지 1564~1671초였다. 거점 조작/로딩/입력 지연은 포함하지 않으며 적절한 장기 반복량을 입증하는 통계 검증도 아니다. XP 배율 외의 신규 반복 콘텐츠는 추가하지 않았다.

## 정수 경계와 일관성

기본 경험치 1단위를 받기 시작할 때의 레벨 구간 배율을 사용한다. 마지막 1단위가 구간 경계를 넘으면 그 단위의 보너스는 다음 레벨로 이어지고, 다음 기본 단위부터 새 배율을 사용한다. 예: Lv.19에서 1XP가 남았을 때 기본 17XP를 받으면 첫 1×4 + 나머지 16×2 = 36XP다.

큰 보상에 이전 구간 배율을 전부 적용하는 허점을 막았고, 같은 기본 XP를 한 번에 받거나 여러 번 나눠 받아도 레벨·잔여 경험치·포인트·총 지급 경험치가 같다. 소수점 경험치나 추가 저장 잔여값이 필요하지 않다.

XP 합계의 레벨별 누적값은 모듈 초기화 시 한 번 만든다. 성장 계산은 최대 4구간만 방문하며 XP 포인트 수만큼 반복하지 않는다. 프로필을 읽기만 하는 함수이고 시계/RNG/비동기 작업/프로필 이관은 없다. 기존 gainXp 경로가 레벨과 포인트의 실제 변경을 계속 소유한다.

## 검증 근거

- 전 레벨 구간 경계, 한 번/분할/1단위 지급의 동등성, 잘못된 수치와 큰 지급, Lv.50 상한.
- 기존 저장의 레벨·잔여 경험치·골드·스킬 장착/강화 유지. 신규 보상 전에는 소급 레벨업하지 않는다.
- 사냥/정찰 동일 지급, 중복 지급 방지, 일시정지 동결, Lv.19→20에서 낮아진 배율 적용.
- 실제 app.js 호스트에서 재료 감각 + 성장 배율, 실제 지급 합계/결과 내역, 정찰 안내와 새 배율, 재로드 후 정찰 중복 방지.
- 최종 npm test 전체 513개 통과, 실패 0개(약 43.3초). 기존 UI/스킬/저장/전투 회귀를 포함한 실행 출력은 test-results.txt에 보관했다.

원자료와 재실행 도구:

- `candidates.json`, `production.json`: `node tools/measure-growth063.mjs`
- `xp-query-cpu.json`: `node tools/benchmark-growth063.mjs`

CPU 자료는 Node에서 1000회 질의 배치 평균을 200회 측정한 것이다. 배치 평균의 p95는 일반 지급 약 0.000079ms, 경계 지급 0.000113ms, 10억 기본 XP 지급 0.000122ms였다. 개별 호출의 꼬리 지연이나 전체 프레임/브라우저/GPU/기기 성능 측정은 아니다.

관리 환경에 control-browser가 없어 실제 브라우저·터치 기기의 글줄/스크롤과 체감 성장 속도를 검수하지 못했다. 다음 실기기 검수에서는 해금 인지, 거점 장착, 3챕터 첫 사용까지의 흐름과 중후반 반복 피로도를 확인해야 한다.
