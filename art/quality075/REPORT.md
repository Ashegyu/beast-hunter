# Alpha 0.75 — 전설 보장과 극옵

드롭 양을 무한히 늘리는 대신 전설을 못 얻는 긴 구간을 줄이고, 같은 등급 안에서도 확인할 가치가 있는 극옵을 추가했다. 기존 그림과 등급별 연출을 사용하므로 추가 이미지 다운로드나 디코드 버퍼는 없다.

| 항목 | 적용 |
| --- | --- |
| 보스 | 첫 번째 장비 전설 이상, 두 번째는 기존 보스 표 |
| 몬스터 장비 보장 | 전설 미만 19회 이후 20번째 전설 이상 |
| 보장 정산 | 바닥 아이템 소유권 예약 때 한 번, 줍기/자동 분해/복구 때 재계산 없음 |
| 극옵 | 영웅~신화의 8%, 선택된 옵션 전부 기존 최댓값 |
| 고대·제작 | 고정 수치와 전용 효과 유지, 극옵 대상 제외 |
| 알림 | 작은 28px 아이템 그림, 등급·이름·핵심 효과 또는 분해 결과 |
| 렌더 상한 | 바닥 이름 1개, 강조 섬광 1개, 기존 음성 10개 상한 |
| 저장 | 선택 정수 legendaryPity와 선택 불리언 perfect, 기존 저장 호환 |

소유권은 기존 pendingLoot 예약 → storeItem 정산을 따른다. 보장 수치는 예약 뒤 같은 동기 실행에서 저장 가능한 profile에 반영된다. 중복 ID는 기존 정산 함수가 거부한다. 가방의 장비·즐겨찾기·저장 빌드 보호, 자동 분해·복구 정산 및 24칸 제한을 변경하지 않는다. 전투 RNG와 드롭 RNG의 분리는 유지한다. 보장에 따른 등급 상승은 옵션 수와 드롭 RNG 소비량을 바꿀 수 있으므로 보스 고대 드롭의 고정 재현 시드도 새 경로에 맞춰 갱신했다.

## 분포와 CPU 측정

실행: `node tools/measure-loot075.mjs`. 각 표본 200,000개, 일반 난이도. 아래 비율은 **장비가 나온 경우**의 품질 분포로, 처치당 확률이 아니다. 보스는 실제처럼 두 개씩 묶어 첫 번째에 보장을 적용했다. 고대 구간의 가중치 자체는 바꾸지 않았다.

| 표본 | 전설 이상 이전 → 현재 | 고대 이전 → 현재 | 전설 없는 최장 연속 드롭 이전 → 현재 |
| --- | --- | --- | --- |
| 일반 몬스터 장비 | 2.9785% → 6.5860% | 0.1090% → 0.1035% | 263 → 19 |
| 보스 장비 | 18.0585% → 59.0225% | 0.3035% → 0.3060% | 58 → 1 |

Node에서 순수 아이템 생성 30,000회를 7번 번갈아 측정한 중앙값은 이전 5.884μs/개, 현재 5.601μs/개였다. 이 차이로 성능 개선을 주장하지 않는다. 브라우저 프레임 시간·GC 정지·GPU 시간·기기 메모리를 측정한 결과가 아니다. 전체 데이터는 loot-measurement.json에 있다.

## 검증

최종 572/572 검사 통과. 전체 기록: tools/reports/loot075-tests.txt.

- 모든 일반 장비 가족·영웅/전설/신화에 대해 극옵 최대 수치, 동일 난수 호출 수, 저장 왕복 확인.
- 실제 전투 경로에서 20번째 보장, 자연 전설 초기화, 보스 3챕터×3난이도 보장 확인.
- 예약/줍기/재접속/가방 보호/자동 분해의 중복 보상·중복 보장 소모 검사.
- 실제 app.js VM에서 극옵의 그림·표식·효과 설명, 일반 장비/재료에 대한 알림 우선순위, 같은 등급 동시 드롭의 음향 우선순위 확인.
- 바닥 이름은 배우/효과 그림 뒤에 그려 가리지 않도록 하고, 이름은 1개만 표시한다. 일반 전투·보스·자동 사냥·60초 제한·즉시 리젠 회귀도 포함한다.

`node --experimental-vm-modules tools/render-loot075.mjs`는 실제 앱 Canvas 합성을 native Canvas로 실행한다. 같은 극옵 표본을 0.74/0.75 앱 코드에 넣어 비교했다. loot-comparison.png, before-arena.png, after-arena.png는 **오프라인 Canvas 렌더**이며 CSS/DOM HUD·브라우저·터치·GPU 검증은 아니다. 브라우저 제어 도구가 없어 직접 브라우저 검수는 수행하지 않았다.
