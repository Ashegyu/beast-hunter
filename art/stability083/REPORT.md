# Alpha 0.83 — save safety and current quality baseline

## Applied

- Added visible save failure/read failure notices outside the hidden footer, retry/reload and an emergency download of the live profile. A storage read failure never writes a fresh default over an unreadable existing record. The same protection holds if a damaged record cannot first be copied to its recovery key because storage is full.
- Added **더보기 → 진행 기록 보관**: download a JSON backup, select a file, compare current/backup summaries, explicitly restore or cancel, and download the record kept before the previous restore. Backup reads are bounded at 256 KiB and checked for format, version, accidental changes and profile structure before native normalization.
- Restoration stores the current live record in a separate rollback key before writing the replacement. Failure of either write keeps the old primary record. After success, interactions stop and the app reloads; stale pagehide/autosaves cannot overwrite the imported record. Native save version remains 8. File backups contain persistent progress and reserved loot/resources, not a resumable running battle.
- Consolidated image-button label sizes/wrapping in buttons.css, introduced shared 44/48px control and 44/56px art sizes, and moved bag/recipe/equipped/codex art sizing into their component styles. Removed duplicated late overrides and the old codex list negative-margin/fixed-size thumbnail rule. Full-frame percentage atlas placement is retained.
- No game image, runtime dependency, damage/drop probability or 60-second timer change.
