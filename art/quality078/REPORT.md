# Alpha 0.78 — 드롭 순간 연출

이미지 자체는 기존 Alpha 0.77 원본을 그대로 재사용한다. 이미지를 생성하거나 수정하지 않았다. 적용 시점만 lootPickup(보관 완료)에서 gearDrop(실제 장비 생성)으로 옮기며 고정된 드롭 좌표에 그린다. 이미지 교차 전환은 0.6초/전설·극옵 1.05초 동안 한 번 진행하고 바닥 아이템의 표시 수명과 분리한다.

기존 도형 dropArrival과 수집 시 loot 문양 렌더를 제거했다. 드롭 이미지는 현재 화면에서 최대 한 개를 크게, 나머지 최대 세 개를 작게 표시한다. 최대 8회의 atlas drawImage와 reduced-motion 고정 프레임 규칙은 유지된다. 이벤트나 이미지는 매 프레임 생성/복사/디코딩하지 않는다. 장비 보관 이벤트·소리·텍스트 알림과 보상 계산은 유지한다.

즉시 스테이지 전환에서 gearDrop 이벤트도 보상 알림과 함께 넘긴다. 같은 이벤트 객체와 기존 TTL을 유지하므로 위치 변경·연출 재시작·중복 지급이 없다. 이전 공격·장판·투사체를 넘기지 않는 규칙도 유지한다. 저장 필드와 원본 어셋은 변경하지 않는다.

npm test: 589/589 통과. 원시 로그: ../../tools/reports/drop078-tests.txt. 실제 app.js 테스트는 몬스터 처치→소유 예약→바닥 연출→캐릭터 이동→수집→연출 만료 경로를 실행하며 이미지가 캐릭터가 아닌 드롭 좌표에 있고 수집 후 다시 시작하지 않음을 검증한다. 기존 등급/극옵 선택·교차 전환·일시정지·20개 동시 이벤트의 상한·보상과 난수 불변·저장 복구·몬스터 장판 부재·챕터 결과 회귀를 포함한다. 일반 스테이지의 마지막 처치 드롭이 다음 스테이지에 남아 기존 TTL만 소비하는 것도 검사했다.

node --experimental-vm-modules tools/render-drop078.mjs는 실제 app.js와 원본 WebP를 native Canvas로 실행하고 실제 정예 처치와 수집을 진행한다. drop-timing.png는 드롭 순간 / 수집 뒤 원래 드롭 좌표에서 남은 연출 / 만료 후를 보여준다. scenes.json에 보관 여부, 예약 여부, 캐릭터·드롭 좌표와 이미지 사각형을 보존한다. 통제된 전투이며 전체 캠페인 직접 플레이를 의미하지 않는다.

HTML 닫힘/ID/로컬 링크, JavaScript 구문과 git diff 공백도 검사한다. control-browser가 없어 브라우저 직접 검수는 생략했다. 렌더 이미지는 실제 전장 Canvas의 오프라인 결과이며 브라우저 CSS 배치·기기 GPU/메모리/FPS·터치·음질은 미검수다. 사용자 컴퓨터와 로그인을 사용하지 않았다.
