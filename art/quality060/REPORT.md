# Alpha 0.60 — 품질 1단계: UI와 조작

## 범위

신규 시스템 도입 전 UI/입력 상태를 점검했다. 사이트 ID·공개 범위·세이브 형식·전투 수치·스킬의 해금과 60초 궁극기 쿨다운은 보존한다. 다음 단계는 타격음/피격 반응/공격 예고와 이펙트 구분, 이후 성장·보상 흐름 점검이다.

## 재현하고 수정한 입력 문제

- 공격을 누른 뒤 일시정지/재개하고 손을 떼면 예전 클릭이 새 공격을 시작했다. 기존 click 경로와 포인터 경로가 같은 명령을 각각 받을 수 있었다.
- 오른쪽/가운데 마우스 버튼도 공격 홀드에 들어갔다.
- Ctrl/Command/Alt+R/T/W/I가 브라우저 동작 대신 스킬·이동·장비 명령으로 처리됐다.
- 회피·파쇄·스킬은 click 시점에만 실행되어 버튼을 뗄 때까지 기다렸다.

포인터의 기본 버튼 누름에서 명령을 한 번 실행하고, 뒤따르는 물리 클릭은 추가 명령으로 쓰지 않는다. 키보드/보조기기 활성화(detail 0)는 유지한다. 홀드 공격의 pointer capture와 joystick의 독립 소유권은 기존대로다. 별도 버퍼·예약 스킬·새 타이머는 도입하지 않았다. 보조 키 조합은 전투 키 처리 전에 반환한다.

기본 공격/회피/파쇄도 양수 쿨다운의 마지막 구간을 0.1초로 표시한다. 0초 이전에 준비로 표시하던 0.05초 임계값을 제거했다.

## HUD 정리

미션·보스 체력·알림·제작 목표를 DOM 순서대로 자동 배치해 숨은 행의 빈칸을 없앤다. 제작 목표는 핵심 전투 정보 뒤로 간다. 높이 680px 이하에서는 챕터 반복 표기를 줄이고 미션명/진행 상황을 두 행으로 표시한다. 보스 알림과 획득 알림이 함께 뜨면 두 열의 간결한 요약을 사용한다. 임시 알림만 말줄임하며 실제 목표/장비 이름은 DOM에 남고 원문을 title에도 제공한다. 가로 화면은 보스명과 안내 요약을 더 간결하게 표시한다.

## 검증 근거

1. 변경 전 테스트 4개가 실패하는 것을 확인했다(브라우저 보조 키, 재개 후 남은 클릭, 포인터 누름, 비기본 마우스 버튼).
2. 수정 후 위 4개 통과.
3. 전체 491개 회귀 검사 통과 후, 30/60fps의 이동+공격 홀드+스킬+회피+일시정지/해제 추가 검사 1개 통과. 총 고유 검사 492개.
4. 보스/미션/보상/제작 목표 동시 표시를 320×568, 390×844, 480×320 앱 호스트에서 검사했다. 긴 보상 이름 원문과 일시정지 상태를 확인했다.
5. 기존 공격/스킬/재생/저장/메뉴 회귀는 실제 app.js와 게임 엔진 모듈을 실행한다. 테스트 호스트는 브라우저 CSS 레이아웃이나 실제 터치 장치를 대신하지 않는다.

## 남은 확인

관리 환경의 control-browser가 없어 실제 브라우저를 실행하거나 기기 화면을 검수하지 않았다. CSS의 최종 픽셀 위치, 브라우저별 포인터 합성, 보조기기 실물 동작, 엄지 도달감과 모바일 GPU 시간은 미확인이다. 오프라인 조판을 실제 화면 검증으로 보고하지 않는다. 이 제한 때문에 UI 전체가 모든 기기에서 완성됐다고 판단하지 않는다.
